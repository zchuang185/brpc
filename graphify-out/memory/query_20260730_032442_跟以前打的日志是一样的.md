# Q: 跟以前打的日志是一样的

## Answer

Expanded from original query via vocab: [event, wait, poll, polling, completion, cqe, rearm, notify, recv]. 新源码在PollCq处理首个事件后必然再次调用WaitCqEvent；若无第二事件且urma_trace_verbose=true，必然打印URMA JFCE event queue drained。当前源码行号也已变化：WaitCqEvent在1685、prepared jetty日志在1925，而旧日志分别为1681和1895。若测试日志完全相同且没有新marker，实际运行的client仍链接旧libbrpc。urma_performance的CMake通过find_library缓存BRPC_LIB，只重编example不会重编或切换brpc库。先用strings检查marker和cmake cache中的BRPC_LIB，再显式指向刚构建的output/lib/libbrpc.a重新链接。上一结论把相同日志直接归因于内层JFCE未drain不够严谨，必须先排除旧二进制。

## Outcome

- Signal: corrected
- Correction: 测试日志若没有新加入的URMA JFCE event queue drained标记且仍使用旧源码行号，说明urma_performance链接了旧libbrpc；应先验证并重新链接新库，再判断JFCE/rearm逻辑。
